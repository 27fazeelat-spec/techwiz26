Injection defence

Documents are data, never instructions

Uploaded files are scanned before anything uses them. All {{ m.attacks }} attack types planted in the test collection are caught, with no false alarms on normal policy text.

{{ icon('shield', 22) }}

Scanned at upload

Direct instructions, fake authority, system impersonation, encoded and zero-width text, markup and prompt-extraction attempts.

{{ icon('x', 22) }}

Quarantined, not deleted

Suspicious sections are kept as evidence, shown in the security report, and never sent to Gemini or used as a requirement.

{{ icon('check', 22) }}

Powerless even if missed

Sources are delimited as data, output must match a schema, and no status is ever taken from the model's own words.

Audit trail

Every decision keeps who, when, what it was before and why.

The application can only insert into the audit log; updates and deletes are refused by the code and, on PostgreSQL, by database privileges. Overrides never overwrite the computed result; both are kept side by side.

Data & access

Least privilege, least data

{{ icon('users', 22) }}

Five roles, checked on the server

Administrator, Training Manager, Reviewer, Manager and Employee. Managers see only their own team; employees only their own plan.

{{ icon('user', 22) }}

No sensitive personal data

Onboarding needs a role, a property, a joining date and experience. National IDs, salaries and health data are never asked for.

{{ icon('file', 22) }}

Secrets stay out of code

API keys and database credentials live in the environment. Database connections use TLS with full certificate verification.
